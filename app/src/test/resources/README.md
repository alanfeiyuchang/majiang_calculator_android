# 国标算番的官方对照数据

`mcr_oracle_cases.txt` —— 1756 条「牌型 → 期望番种 / 总分」。

**期望值不是我们自己推的**，来自 **PyMahjongGB**（北大 Botzone 国标麻将比赛官方算番器，
逐字 vendor 了 ChineseOfficialMahjongHelper 的 mahjong-algorithm）。

格式（13 段）：
`手牌|副露|和牌张|门风|圈风|自摸|总分|番种…|和绝张|杠标志|牌末标志|保留|花牌数`
- 手牌含和牌张；副露 `kind,牌`，kind ∈ chow(吃，写**起始**牌) / pung / ekong / ckong
- 门风、圈风为 1–4（东南西北），载入时减 1 转成引擎的 0 基
- **总分是含花总分**，对应引擎的 `totalPoints`（`scoringPoints` 不含花，那是判起和线用的）
- 番种写成 `幺九刻*2` 表示同一番种计了 2 次，个数也要对上
- 官方的「独听・嵌张 / 独听・单钓 / 独听・边张」对应我们的 坎张 / 单钓将 / 边张
- 「杠标志」官方把**杠上开花**和**抢杠和**合成同一个标志：自摸时读作前者，点炮时读作后者。
  「牌末标志」同理对应**妙手回春** / **海底捞月**

## 覆盖率——这份语料前两版都栽在这里

第一版：0 条自摸、0 条特殊牌型、23/82 番种零覆盖，于是「12000 副 100% 一致」是假象。
第二版：13 个番种零覆盖，而且**所有场景标志位全是关的**，抢杠和 / 和绝张 / 杠上开花
的校正逻辑从没被对照过——三个真实的算错就藏在那里。

**改语料前先量覆盖率。** 现在这版覆盖全部 82 个番种（每个 ≥3 例，七星不靠 2 例），
并且五类场景标志各有数百例。来源：普通随机牌 + 稀有型加权 + 手工构造
（一色双龙会 / 一色四同顺 / 一色四步高 / 三色双龙会 / 全大 / 全带五 / 全求人 / 四杠
这些随机牌几乎打不出来的番种）。

构造牌型时注意：**吃写起始牌，起始牌 > 7 的顺子根本不存在**，
写了 `chow,8m` 两边算番器都不会报错，只会给出垃圾结果。

## 已知的、不打算追的差异

在 215 万副的差分里，**总分零分歧**；有 0.09%（1972 副）总分相同但番种**名字**不同，
全部是同一类：一副牌能拆成好几种得分相同的读法时，取哪一种。例如

    11223344m789p345s 和 3 万 → 拆成 123+123+44 是「边张」，拆成 234+234+11 是「坎张」

两种都是 1 分。官方算番器取它自己先枚举到的那个，同类牌型上时而取边张、时而取坎张
（`66778899s` 就取的坎张），可见那是实现细节而非规则，98 规则里也没有这条。
同一个拆解**内部**的优先级（边张 > 坎张 > 单钓将）是官方明文写死的，那条我们跟。
